# 对照实验协议

> 用途：**证明"某个上下文改动真的让 AI 更快走对链路"**。
> 一份实验只回答一个问题：「把 A 改成 B，同一任务下 AI 是变快、变直、还是变对？」
> 配套工具：`tools/ab_plan.py`（规划与派发）＋ `tools/ab_collect.py`（收数与对照）＋ `tools/compare_runs.py`（两次执行的结构 vs 波动判别）。**思考过程直接读 `trace.jsonl` 的 `kind=reasoning`，不另做统计工具。**

---

## 一、八条纪律（缺一条，结论就不成立）

| # | 纪律 | 违反的后果 |
|---|---|---|
| 1 | **同一任务**：所有配方的任务正文**逐字相同** | 变的是任务，不是上下文，归因不成立 |
| 2 | **只换上下文**：配方之间**只许差"上下文"那一段** | 同上 |
| 3 | **并发派发**：一次发完，不串行 | 时段/环境漂移会污染对比 |
| 4 | **重复 ≥2 次**：每个配方至少跑 2 次 | 单次读数分不清"配方差异"与"随机波动" |
| 5 | **判据机械可判**：写清"什么算通过" | 判不了就只能靠感觉，等于没测 |
| 6 | **人先做过一遍**，记下人的耗时 | "不能比人慢"没有基准 |
| 7 | **等结束再收数**：`ab_collect` 会挡未结束的子会话 | 半成品读数会得出**相反的**配方优劣 |
| 8 | **认领标签逐字进 `description`** | 收数时认不出子会话，数据作废 |

---

## 二、一次实验的完整流程

### ① 出题

写一份实验定义 `<实验id>.yaml`：

```yaml
id: exp-00X-<主题>
scenario: <一句话场景，给人看>
task: |
  <所有配方共用的任务正文：要干什么、交回什么格式>
verdict: |
  <什么算通过：必须机械可判；判不了就写清"谁来判、判什么">
repeats: 2
timeout_minutes: 20
variants:
  - id: <配方短名>
    label: <人读的配方说明>
    inject:                  # 这一段的差异 = 本次实验的自变量
      - file: <仓根相对路径>   # 只给指针（推荐）
        note: <一句为什么给这个>
      - text: |              # 或直接给一段注入文本
          <…>
```

### ② 规划

```powershell
python tools/ab_plan.py --spec experiments/<实验id>.yaml --repo <业务仓绝对路径> --out experiments
```

产出 `<实验目录>/`：
- `plan.json` —— 窗口起点、配方、认领标签、注入项的 sha256（**用于事后证明"给的就是这些文件"**）
- `briefs/<key>.md` —— N 份可直接当 prompt 用的任务书
- `DISPATCH.md` —— 派发清单

### ③ 派发

按 `DISPATCH.md`，**并发**调 N 次 `subagent`：

```
description: <逐字用 DISPATCH.md 里的 dispatch_label>
prompt: <briefs/<key>.md 的全文>
run_in_background: true
```

> ⚠ `description` 里的标签就是**认领凭证**。写错一个字，收数时认不出来（工具会报"未认领"，不硬塞）。

### ④ 收数

```powershell
python tools/ab_collect.py --exp experiments/<实验id> --dispatcher <派发会话id>
```

它会：按标签认领子会话 → 逐个跑 `dsh_trace` 抽取 → 出 `results.md` / `results.json`。

**若提示"有 N 份尚未结束"：等它们结束再跑一次。** 不看聚合结论。

### ⑤ 判据回填

按 `verdict` 逐条人工判，写 `verdicts.json`：

```json
{ "<key>": { "pass": true, "note": "<依据>" } }
```

再跑一次收数并带 `--judge verdicts.json`，得到**通过率**。

### ⑥ 归因

**只看同一实验内的配方间差异。**
- 哪个配方 K1~K5 更好 → 把赢的那条固化进项目的接手面/动作卡/事实卡
- 然后**回到 ①**，出下一道题

## 三、五个考核指标（口径固定，不许各实验自定义）

| # | 指标 | 口径 | 来源 |
|---|---|---|---|
| **K1** | 完成时间 | 接到任务 → 交出可判结论 | `trace.jsonl` 首末事件 |
| **K2** | 开工税 | 接到任务 → 第一个推进动作 | `manifest.metrics.milestones` |
| **K3** | 调用过程 | 工具调用数、重复读浪费、只读长段、自建脚本数 | `manifest.metrics` ＋ `trace.jsonl` |
| **K4** | **零纠结** | **读思考块**：五类纠结点（方法层 §3.2）还有没有 | `trace.jsonl` 的 `kind=reasoning`（**人读，不靠统计**） |
| **K5** | 是否走对链路 | 判据通过率 | `ab_collect.py --judge` |

**K5 是唯一的"对不对"；K1~K4 是"快不快、绕不绕"。**
**压时间必须以 K5 不掉为前提**——这是本协议最重要的一条。

---

## 四、读数的四个陷阱

| 陷阱 | 表现 | 怎么避 |
|---|---|---|
| **半成品** | 子会话还在跑就收数，工具数偏小 | 纪律 7；工具会主动报警 |
| **同机并发污染成本** | 用量账本按时间窗并入，四次并发会互相叠加 | 成本**不做配方间对比**；只用思考字符/工具调用 |
| **单次波动** | n=2 时均值可能被一次异常拉偏 | 看区间不只均值；重要结论加到 n≥3 |
| **绝对值跨实验比** | 拿这次 3 分钟比上次 5 分钟 | 环境/时段/任务都不同 ⇒ **只在同一实验内比** |

---

## 五、判定"这个改动值得固化"的门槛

满足**全部**才固化进项目：

1. **K5 不下降**（通过率不退）
2. **K1 或 K3/K4 有明显改善**（不是噪声级差异）
3. **改善能解释成因**（说得清"为什么这样改会变快"）
4. **不依赖某一次的具体内容**（换一个任务/节点仍成立）——否则它只是"这次运气好"

第 4 条最容易被忽略：**要固化的是"形态"（如"给一条权威指针"），不是"内容"（那个具体文件）。**

## 六、已跑过的实验（留档，供后续对照）

| 实验 | 自变量 | 结果 |
|---|---|---|
| `exp-000-pilot` | 什么都不给 vs 多一条权威指引 | 通过率都 1.0；**工具调用 -30%、思考量 -56%** |
| `exp-001-brief-shape` | 大任务书（必读+红线+产物清单）vs 3 行任务书 | 通过率都 1.0；**时间 -41%、工具调用 -49%、思考量 -73%**；成因核实见该目录 `成因核实.md` |

两轮共同指向同一结论：**任务书里的"必读清单+红线+产物清单"不提高正确率，只提高成本。**

### 6.1 一个"成因核实"的样板

协议第 5 节要求"改善能解释成因"。`exp-001-brief-shape/成因核实.md` 是这么做的：

1. 从 `local/traces/<run>/trace.jsonl` 把**每个子会话的调用链**列出来（素材是派生物，按需重生成，见 `local/traces-重生成.md`）；
2. 找出**打空/超时**的调用，逐条引原文（形如 `Error: cannot read "<工作区根>\demands\INDEX.md": not found`）；
3. 对比两边的**调用形态**（大任务书两轮 10 次仓根宽搜 vs 3 行任务书各 1 次）；
4. 得出机制：**不是"多读了几份文档"，而是"多了一次路径解析"** —— 并据此补强了一条可执行要求（任务书里的路径必须可一步解析）。

> **没有这一步的对照实验，只能证明"哪个更快"，不能证明"为什么快"，也就无法固化。**
