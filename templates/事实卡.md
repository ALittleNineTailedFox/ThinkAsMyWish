# 事实卡模板

一张卡 = 一条已定结论。它要解决的是：结论已写在仓里，AI 却靠现场试错重新发明一遍。

文件命名建议：`事实/<主题>-<结论短名>.md`，或一条一个文件。

---

```yaml
结论ID: <唯一 id，下游引用它>
一句话: <结论本身，可直接照着做>
权威源: <文件路径:行号 / 记录ID / 命令回执>     # 必填；无锚点的结论不进任务书
冲突以谁为准: <本条与其他说法不一致时以谁为准>   # 必填；缺这一栏，AI 会自己仲裁
定于: <日期> by <谁定的>
适用范围: <在什么条件下成立>
不适用: <什么条件下这条结论是错的>              # 必填，防止被过度泛化
状态: <有效 / 已作废（作废要写被谁取代）>
```

同一事实只允许一处权威。两条纪律：

1. 作废即删：结论作废时从活文件里删掉，不留"此处曾有一条已作废结论"。过去的对与错去变更记录里找。
2. 改权威源＝同批改入口：宣布新权威源的同一个动作里，把入口件、技能、手册里的旧引用清掉。先宣布后执行，等于把仲裁成本转给 AI。

## 1 一句话结论

<用"照着做"的语气写，不写分析过程。>

反例（AI 读到这种写法不会停手）：

> 「`decimalAttribute → null` ⇒ 参数无效分支」

正例：

> 「某字段为空时该参数静默不生效；要让它生效，必须先注入该字段。」

差别：反例是实现细节，AI 还要自己推一步才能用来停手；正例可直接照做。
判据：AI 读完这条，还需不需要自己补一个判断？需要就重写。
