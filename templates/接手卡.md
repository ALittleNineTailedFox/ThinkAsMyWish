# 接手卡模板

用法：复制到目标项目仓根（建议命名 `AI-接手.md`，或并入仓根 `AGENTS.md`）。

要求：AI 读完这张卡，不提任何问题就能开工。
判据：拿一个新会话只给这张卡 ＋ 一句具体任务，看第一个推进动作多久出现。超过 5 分钟＝这张卡没写好。
不内联知识，全部写指针；指针用仓根相对路径（`../` 在搬迁后会腐烂）。

---

## 1 这是什么项目（≤5 行）

- 一句话：<项目在做什么>
- 产物是什么：<AI 干完活应该留下什么>
- 一切路径的基准：仓根（`<绝对路径>`）

## 2 动手前必读（缺一不干活）

只列"不读就会走错"的。超过 5 条，就是把文档清单塞进来了。
每条必读都要能被核对：不是"读了入口"算读过，要能说出读了哪份正文。

1. 任务书：这次干什么、验收判据是什么。（用户直接说的，以用户为准）
2. 我在哪条链的哪个节点：读 `<链路索引路径>`，定位节点 id。
3. 这条链的这个节点该看什么：按节点 id 去 `<路由路径>` 取指针。
4. 我这类活的手册：`<手册索引路径>` → 读对应那一本的正文，不是只读索引。
5. 这个动作怎么执行：`<动作卡目录>` → 找到对应动作卡，照第一条命令原文执行。

本卡里出现的每一个路径、每一条命令，都必须真实存在且在役。两类失效：

- 指向已被删除的文件：一条必读项静默消失，AI 跳过且不自知。
- 规则已宣布唯一权威源、旧中间层也已删除，但本卡还在说旧话（甚至写着已删的命令）：AI 只能自己仲裁信哪个。这不是它判断失误，是入口在命令它。

存在性校验归维护者，不归接手的 AI：改完这张卡，由改卡的人或 CI 跑一条命令把路径与命令逐个验存在，失效即当场修。
不要写成"AI 开工第一步先验一遍"——那是往每个接手者的动作序列里加一轮。AI 接手时直接照抄本卡；照抄出错，是卡没维护好。

判据：凡 AI 会照着做的地方，只许出现现在对的东西。过去的对与错去变更记录里找。留痕是给人追溯用的，与执行面混在同一文件里，AI 分不出来。

## 3 要什么 → 去哪里（只给指针）

每个"想要"只能指向一个地方。同一件事指两处，AI 就必须自己仲裁。
停用的字段、退役的命令、旧口径，不许以"历史留痕"为名留在本区。

| 想要 | 去哪 |
|---|---|
| 这条链的全部节点 | `<链路索引>` |
| 某个动作的一条命令 | `<动作卡目录>` |
| 已经定过的结论 | `<事实卡目录>`（引用带锚点） |
| 平台能力 / 可调用的东西 | `<能力索引>` |
| 通用坑 | `<坑索引>`（按主题分片，先路由再读，别整篇吞） |
| 环境与纪律 | `<规范路径>` |
| 进度 / 当前状态 | `<一条命令>`（只此一处；不再有台账文件、索引状态列、清单快照） |
| 历史（过去的对与错） | `<变更记录路径>`（AI 干活时不读） |

## 4 边界（AI 不得违反）

- <哪些目录/资源只读>
- <哪些动作需要人放行>
- 不自建已有的能力：动手前先查 `<能力索引>`。
- 机械动作里不塞阅读清单。
- 被污染的批次原样重跑，不改派、不降级。
- 人已经给过的清单／日期／范围就是本次权威输入：先按它做，缺的才问，一次问清；不回头重问"是不是这几个"。
- 判据已定的活只做判定：没有对应判据的现象只进观察区，不进结论、不据此给别人派活。

## 5 升级路径（"没有"不等于"做不到"）

按顺序自问，全否才允许上报：

1. 既有资产（索引/技能/清单）里有现成姿势吗？
2. 仓内有先例吗（历史产物、脚本、提交）？
3. 表能插、键能配吗（这是平台限制，还是自己可控的参数）？
4. 真平台级资源缺失 → 上报，带上以上三问的答案与实锚。

## 6 角色边界

- 统筹者（派活/汇总/验收）：不亲手写业务产物、不自己调试、不通读原仓。
- 执行者（领一件活独立干）：做完把产物落成文件。
- 两种角色同一条：没读到业务就下结论＝违例。"不是问题"和"是问题"两边都要有业务与数据背书。
