# 动作卡模板

一张卡 = 一个明确动作。
明确动作 = 已有命令或接口、判据可机械读取的动作。
任务书里有现成命令的，开工即跑；只有阅读清单的，开工税高一个量级。

文件命名建议：`动作卡/<链>-<节点>-<动作名>.md`（如 `动作卡/<业务链>-触发-单枚验命中.md`）

---

```yaml
动作: <动作名>
所属链: <链名>
节点: <节点 id>
适用: <什么情况下用这张卡>          # 一句话，让 AI 认出"这就是我这次要做的"
禁区: <什么情况下不许用这张卡>        # 一句话，防止误用
```

## 1 动作（一条命令原文，照抄）

```powershell
<把那条命令原样写在这里，含所有参数与默认值>
```

必须是一条能直接跑的命令，不写"参考某文档""按某规范执行"。
必须含仓根（先 `cd <仓根绝对路径>`，或写绝对路径）：只给文件名不给仓根，AI 会先在工作区根扑空，然后开始宽搜。
必须多步时按序编号、每步一条命令；能封装成一条就封装成一条。

## 1.1 环境映射（换环境只改这里，不改判据）

卡里只出现逻辑名，某个环境的具体表名、路径、地址全部收进这张表。
硬编码环境前缀的后果：换环境后 AI 要重新确认"在不在、分区什么形态、字段叫什么"，判定退回考古。

| 逻辑名 | 本环境实名 | 备注（分区列／库／端口） |
|---|---|---|
| `<逻辑对象>` | `<本环境实名>` | `<分区列 / 库名>` |

## 2 判据（怎么算做成了）

| 判据 | 读法 | 成功条件 |
|---|---|---|
| <判据名> | <库行 SQL / 回执字段 / 日志关键字> | <明确的值或条件> |
| <异步动作的收敛点> | <状态字段> | 等到 `<具体状态值>`；"进行中"不算完成 |

优先级固定：库行（走索引列） > 接口回执字段 > 链路节点日志。
有库行判据可用就不用节点链：节点链每次 4~5 分钟，库行秒级。
异步动作（终止／提交／部署／删除）必须写明收敛状态值。读到"进行中"就往下走，这一轮白跑。

一次执行只交一份 ≤25 行的回执：

```
动作：<命令>
关键回执：<字段=值>
结论：<一行>
清场：<一行，或"无需清场">
```

## 3 前置与清场

- 前置：<需要先有什么；没有怎么办（另一张动作卡 / 升级路径）>
- 依赖：<谁会依赖这批数据或这个状态存在？手工清掉会不会拆了后续动作的前置？>
- 清场：<跑完要删什么、要恢复什么；"由被调方负责清理"的不要先动>
- 共享资源：<这个动作会写哪个可写单元？并发时认领它的 id>

## 4 常见坑（写验证过的，不写想象的）

| 现象 | 真因 | 怎么避 |
|---|---|---|
| <症状> | <真因> | <做法> |
| 报错文案在自己源码里 grep 不到 | 判据在外部系统（平台／上游／网关） | 先定位归属再设计实验，不在自己这侧连提假说 |
| 读到"终止中／提交中"就往下走 | 异步动作没有收敛判据 | 写明等到哪个状态值 |
| 手工清场后后续动作必然失败 | 清掉了被调方的删除对象 | 清场前先问谁会依赖它存在 |
| 定性成"平台能力缺口" | 没先找反证 | 库里有该形态的旧数据、旧用例全绿 ⇒ 是自己配方缺一步 |

能做进命令默认行为的纪律，不只留在文本里。例：把"某参数用错会静默返回空"做成那条命令自己的提示，而不是指望 AI 记得读文档。
这是形状，不是门禁——它在 AI 做功时生效，不新增一轮。要加的若是"事后再跑一遍验合规"，别加进 AI 的必读与动作里。
