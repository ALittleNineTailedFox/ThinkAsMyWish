# ThinkAsMyWish

**让 AI 只输出你期望的东西。**

一套控制 AI 上下文与思考过程的开源方法论。名字就是目标：**Think As My Wish**。

---

## 它解决什么问题

你给 AI 一个明确的任务，它花了很久，产出却不对——不是它不聪明，是**它在替你补上下文**。

真实的两个样本（同一套流程、同一天）：

| | 会话一 | 会话二 |
|---|---|---|
| 墙钟 | 5.5 小时 | 11 小时 |
| 派出的子 agent | 43 个 | 38 个 |
| 工具调用 | 2,302 | 3,530 |
| 最终拿到 | 一条硬结论 ＋ 一片未验 | 核心问题到结束仍是**未定** |

**AI 自己在复盘里写的**：

> 「我的错误不是"判断力不行"，是**该读的没读，然后拿推演填空**。」
> 「这次之所以绕，主要不是任务难，是**我把"看起来最省事的推演"当成了"核实"**。」

---

## 核心主张

> **上下文工程不是"多给点资料"，是"让 AI 不必推理"。**

判据只有一条：

> **AI 的思考里，还应不应该出现「权衡／猜／找」？**

正常的思考是「**这件事该怎么做**」；病态思考是「**我该信哪个数 / 该去哪找 / 做到哪算完 / 走哪条路**」——后者全部是 AI 在替你把上下文补齐，每补一次就多一次押错的机会。

### 要清零的五类纠结

| 类 | 思考里的样子 | 上下文里缺的 | 补什么 |
|---|---|---|---|
| **A 权威不明** | "Hmm… 信哪个？" | 唯一权威源 | **事实卡**：结论 ＋ 实锚 ＋「冲突以谁为准」 |
| **B 位置不明** | "在哪？走哪条通道？" | 可一步解析的位置 | **接手面**：路径含仓根 ＋ 每个动作一条命令 |
| **C 边界不明** | "要不要也…？" | 范围行 | 任务书写死「做什么／**不做什么**」 |
| **D 做法不明** | "用 A 还是 B？" | 一条路 | 明确动作只留一条命令；写明谁定 |
| **E 判据不明** | "算不算做成？" | 机械判据 | **动作卡**的判据栏 |

## 已实测的结论

| 对照 | 自变量 | 结果 |
|---|---|---|
| 实验一 | 什么都不给 vs **多一条权威指针** | 通过率都 1.0；工具调用 **-30%**、思考量 **-56%** |
| 实验二 | 大任务书 vs **3 行任务书** | 通过率都 1.0；时间 **-41%**、工具调用 **-49%**、思考量 **-73%** |

同一结论：

> **必读清单＋红线＋产物清单不提高正确率，只提高成本。**

（「思考量」只是结果指标，**不是目标**。目标是思考里零纠结。）

## 怎么用

### 1. 观测：先有素材本体

没有可信观测，一切指标都是自评。

```powershell
python tools/dsh_trace.py --session <会话id> --out <目录> --verify
```

出一份素材：**上下文 ＋ 思考过程 ＋ 调用链**（`trace.jsonl` / `manifest.json` / `report.md`）。
它保证：幂等（两次抽取字节一致）、完备（源记录逐条有归宿）、对账（字符与源一致）、诚实（格式变了报错，不猜）。

> **思考过程不需要另做工具**——`kind=reasoning` 就是思考块全文，**直接读**。

### 2. 对照：同一任务，只换上下文

```powershell
python tools/ab_plan.py   --spec <实验定义.yaml> --repo <业务仓> --out <目录>
python tools/ab_collect.py --exp <目录> --dispatcher <派发会话id> [--judge <判据.json>]
```

并发派发同一任务 × N 个上下文配方，然后比**完成时间 / 调用过程 / 零纠结 / 判据通过率**。

### 3. 接入：把项目改造成「AI 接手即走对链路」

用 `templates/` 的四张卡：

| 卡 | 回答什么 |
|---|---|
| **接手卡** | AI 进项目第一秒该知道什么（读完**不需要提任何问题**） |
| **链路卡** | 这条链有哪些节点、每个节点判据在哪读 |
| **动作卡** | 一个明确动作 = **一条命令 ＋ 一个判据 ＋ 一个交回** |
| **事实卡** | 已定结论 = 一句话 ＋ 实锚 ＋ 冲突以谁为准 |

## 仓库结构

```
METHOD.md                主方法论
docs/对照实验协议.md      实验协议（八条纪律＋四个读数陷阱）
templates/               四张卡模板
tools/                   五个工具
local/                   本地产物区（★ 不入 git：具体项目的内容与中间过程）
```

**`local/` 是刻意的设计**：方法论要能被别的组织直接拿走用，所以具体项目的一切（业务细节、路径、数据）都留在本地。
每优化一个新项目，就在 `local/targets/<项目名>/` 加一个目录。
